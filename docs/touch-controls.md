独立的油猴脚本，同时支持 **Holodex 多视图（YouTube iframe）** 和 **普通 YouTube watch/live/shorts 视频页（含移动版）**。v0.6.7 直接在原脚本中整合左上角常驻小标签，无需打开详细控制面板就能查看时间或 YouTube 原生 Connection Speed；保持 v0.6.6 已修复的直播播放位置显示和真实测速逻辑。保留单排五档倍速、手机画质入口、播放后触控修复与 Holodex 智能自动播放；不增加第二个脚本。

## 安装与升级

1. 在 PC 或安卓浏览器的 ScriptCat / Tampermonkey 中更新原有 **Holodex Touch Controls** 脚本，**不要同时启用两个版本**。
2. 刷新 `holodex.net/multiview` 页面，必要时也刷新 YouTube。**智能自动播放仅适用于 Holodex 多视图 YouTube 格子**；透明音量手势及快捷播放控制额外支持 `youtube.com/watch`、`youtube.com/live/...`、`youtube.com/shorts/...` 和 `m.youtube.com` 的相应页面。YouTube 页面不会启动 Holodex 自动播放引擎。
3. 触摸手势和播放时间通过 Holodex 页面运行。**Connection Speed、Buffer Health、Live Latency 和原生分辨率**则还需要脚本获得在 `www.youtube.com/embed/*` / `www.youtube-nocookie.com/embed/*` 等第三方 iframe 内运行的权限。
4. 原来的 Cleaner、Quick Add、Channel Name Fix 不需修改。

## v0.6.20：带单位延迟与更清楚的状态区

用户的 v0.6.19 实机报告已确认：getStatsForNerds 和 getStatsForNerds(0) 均返回 `live_latency_secs: "0.00s"`。此前解析器仅接受纯数字，该带单位字符串被当成无效值，造成「未提供」。现在识别明确的 s／秒／seconds 与 ms／毫秒／milliseconds 后缀，按值中明确单位换算；没有后缀时采用字段单位。负数、非有限数和混杂文本仍不当成当前延迟。

- **直播**：标题下显示独立紧凑状态行「● 直播 · 直播延迟」，右侧显示原生秒值；没有有效值时显示「暂未提供」。标题最多显示两行，标识不再占用标题宽度。
- **录像**：隐藏整行直播延迟，播放时间标签改为「录像 · 播放时间」，保留当前位置／总时长。
- **尚未确认类型**：状态区显示「待确认／视频状态／识别中」，避免把类型未知误写成正在直播。
- 普通 YouTube 与 Holodex 多视图使用相同状态组件；画面 HUD 继续只显示时间／速度，录像／直播文字只出现在打开的面板里。
- `0.00 s` 如实反映播放器报告为零，**不据此宣称实际端到端延迟为零**，不使用缓冲值或样本数组估算。

语法检查与 **49 项自动测试通过**；新增覆盖用户实际 `"0.00s"`、秒／毫秒后缀、无效字符串、直播／录像／未知状态切换、普通播放页被动读取。双源本地模拟浏览器验证多视图及普通 YouTube 面板显示 `0.00 s`、标题区没有标识、切换录像隐藏延迟并显示总时长，未见页面脚本错误。本地使用用户报告格式构造数据，并非对用户实站的观看延迟测量。

## v0.6.18：实际延迟字段适配与纯时间 HUD

## v0.6.17：区分直播与录像，恢复总时长并解释延迟缺失

### 已确认的代码问题

- isLiveContent 表示视频属于／曾属于直播内容，直播结束后的录像也可能保留 true。旧版把它直接当成当前正在直播，导致录像时间只显示位置、隐藏总时长，同时去查询不适用于录像的直播延迟。
- 旧版还会搜索整个网页的直播徽标，推荐栏里其他直播也可能干扰当前视频判断。现在只检查当前播放器自己的直播界面，并检查返回元数据的视频 ID，避免 SPA 切换后使用上一条视频的状态。
- 面板一直使用固定「播放时间」标签，没有显示实际识别类型；原生媒体 duration 不可读时，iframe 时钟也没有完整使用播放器 API、视频元数据和 Holodex 后备时长。

### 新的显示和判定

- 面板标题旁明确显示 **直播／录像／待确认**，HUD 时间模式也带同样类型文字。
- 根据当前直播标记、直播结束标记、播放器明确的 isLive／isLive() 状态及当前播放器直播徽标判定。历史 isLiveContent 单独存在时为待确认；多视图可用当前格子的 Holodex past／live 状态补充未知结果，但不覆盖已确认的播放器状态。
- 录像显示 **当前位置 / 总时长**。时长优先实际媒体，缺失时依次读取播放器 getDuration、匹配视频的 lengthSeconds，以及 Holodex 包装接口；当前位置和时长可以从不同可靠来源组合，不再因 iframe 只有位置而丢弃后备总时长。
- 真正直播仍只显示媒体播放位置，不将有限 DVR 窗口当成直播总时长；状态未知时不猜测成直播／录像，也不冒充已知总时长。

### 为什么有网速却没有延迟

这些指标是不同字段。能读到网速、分辨率或缓冲，不代表相同接口返回了直播延迟。旧版「未提供」还混合了误判录像、接口不存在、接口有数据但无延迟字段、字段单位不明确等情况，单凭这个词无法确定用户当前视频的具体原因。

脚本菜单新增 **「诊断视频类型／时长／延迟」**。有打开面板时诊断当前视频，否则列出最多 12 格。报告类型依据、时间与总时长来源、明确的延迟缺失原因、getLiveLatency 是否存在及返回状态、各统计接口是否存在／有延迟字段，以及原版统计是否开启。只读取数据，不自动开关或隐藏原版统计，不上传报告；不收集整段原始调试数据。

录像显示「非直播」；类型未知显示「状态未确认」；真正直播没有可解析字段才显示「未提供」。对于真实直播，准确缺失原因需读取该视频的诊断报告，不能从截图反推。普通 YouTube 面板同步修复类型标识和录像时长；详细延迟诊断菜单位于 Holodex。

## v0.6.6：为什么播放时间没了，如何恢复

此前 v0.6.5 为避免将直播滚动 DVR 窗口长度（例如 1 小时）当成直播总时长，把检测为直播的视频改为只显示「状态｜🔴 直播中」。这一修改过度简化，**错误地取消了比直播状态更重要的播放时间**。

### 本版修复

1. **普通 YouTube**：面板顶部始终保留「播放时间」。点播或已结束回放显示例如 `0:01:41 / 0:03:35`；实时直播也显示实际播放器的当前时间轴位置（如 `0:16:13`），将「🔴 直播中」放到下方单独的小字说明。**直播时间轴位置不是开播以来总时长**；不再把不断滚动的 DVR 窗口当成直播总时长。
2. **Holodex 多视图**：通过原有 Holodex 页面代理获取 `ytPlayer.getCurrentTime()` 等数据，恢复并加强「播放时间」卡片。普通视频显示当前进度及总时长；直播展示当前播放位置，在下方独立标注直播状态，不影响「直播延迟」统计。
3. **播放时间尽量抗播放器重建**：普通 YouTube 页优先使用当前实际视频播放器下属的 `HTMLVideoElement.currentTime`；若视频元素缺失、未准备好，再使用 YouTube 播放器 `getCurrentTime()`。总时长在视频元素缺失时可回退到 `getDuration()`。页面跳转／Shorts 切换时尽量避免引用旧视频。
4. **连接速度不闪烁**：沿用 v0.6.5 的 YouTube 原生 `getStatsForNerdsData()`、`getStatsForNerds()`、统计面板 DOM 等采集路径。原生数据偶尔缺少连接速度时，最多**保留 6 秒钟内同一视频最近一次真实的 Mbps 值**，并标记为「上次真实采样 X 秒前」；若 6 秒内没有新数据或当前换了视频，显示「—」。**不是网络测速或自行推算**，浏览器未暴露原生带宽字段时仍可能没有结果。
5. **优先级与布局**：播放时间字号加大，Holodex 与普通 YouTube 界面都突出时间，同时继续展示分辨率、Buffer、Connection Speed、五档倍速和音量。既有 Holodex 多视图自动播放设置未改变。

## v0.6.3：恢复普通 YouTube 面板实时连接速度

根据用户反馈，普通 YouTube 视频的「播放时间」「实际分辨率」「缓冲时长」都有数据，但「连接速度」始终是 `—`。问题不是宽带真的为零：Holodex iframe 使用的是较完整的 YouTube 原生统计采集，而 v0.6.2 的普通 YouTube 面板仅读取 `getStatsForNerdsData`、`getStatsForNerds` 返回对象中的少数键，**没有持续启用和采集 YouTube 原版 Stats for nerds**。

现在普通 YouTube 面板采用与 Holodex 之前有效方案同类的机制：

1. 打开面板时，若当前播放器支持 `isVideoInfoVisible()`／`showVideoInfo()` 且原生统计尚未开启，则先将原版统计覆盖层设置为不可见、不可触控（仍保持 DOM 可更新），再开启原版 Stats for nerds。
2. 从 `getStatsForNerdsData()`、`getStatsForNerds()`、`getDebugText()` 中读取有明确 Kbps 单位的连接速度；原生统计在更新时，优先使用原版实时 DOM 中标注 `Connection Speed`／`连接速度` 的数值。
3. 面板打开期间持续更新实时值。普通 YouTube 切换视频或替换播放器时，重新检查原生统计状态；如果 YouTube 内部重置了原版统计，会尝试恢复采集。
4. 关闭快捷面板、切换到不支持的页面或离开网页后，关闭**本脚本主动开启的**原版统计，并移除静默遮盖；原先由用户自己打开的原版统计不会被关闭。
5. YouTube 当前不提供可用连接速度时仍显示 `—`，不把视频码率、缓冲增长速度、网络测速结果伪装成 Connection Speed。显示的 Mbps 是原生 Kbps 数值换算。

**播放时间两项的含义：** `0:01:41 / 0:03:35` 表示「当前播放到 1 分 41 秒 / 总时长 3 分 35 秒」。这是两种含义，不是两个播放计时器。对于直播，浏览器提供的第二个时间有时是 DVR 可回看区间长度，不应视为主播实际开播时长。

**回归测试：** 在模拟的 YouTube 原版统计 DOM 中，将 `4,300 Kbps` 改为 `14,700 Kbps`，可验证自定义面板每次读取都跟随更新；验证打开时静默开启，关闭时恢复原版状态；验证播放器有直接 Kbps 数据时不依赖 DOM，缺少数据则不捏造值。**实际安卓 Tampermonkey 的网页行为仍需用户实测**。

### 具体代码修复

1. 以前静音回退执行顺序为 Holodex `vm.setMuted(true)` 后**同一同步任务立即**调用 `playVideo()`。由于 Vue 组件通过 watcher 更新 YouTube iframe 的静音状态，播放请求可能比静音消息更早到达，仍被判断为「有声自动播放」。
2. 现在在**你明确允许静音回退**的前提下，只有**暂停或尚未开始的视频**检测到浏览器拦截或多次失败后，才先调用 YouTube IFrame API 的 `mute()`，再调用 Holodex 的 `setMuted(true)` 同步界面，**延迟约 220 毫秒**后检查视频仍未播放，再请求 `playVideo()`。
3. 若正在播放、缓冲中、手动暂停保护中，均不会触发该静音动作。延时期间如果视频已经播放、页面隐藏、布局更改或关闭自动播放，则不再启动。
4. 新增油猴菜单 **「▶ 允许被拦截的视频静音启动」**：每次手动开启都会先明确征询；启用后写入已有的 Tampermonkey GM 设置，随刷新保留，并向播放器同步配置。
5. 在「诊断多视图自动播放状态」中，如果已有浏览器拦截事件而静音回退仍关闭，将提示是否**仅对未播放视频开启静音回退**。确认后重试之前受拦截的视频，无需再次切换总开关。
6. 诊断增加「静音指令已发出，等待播放」与「静音回退请求次数」，并修复已经恢复正常播放时仍错误显示旧的浏览器拦截信息的情况。
7. 即使静音方式仍被浏览器拒绝，也保持播放尝试次数上限。**不会因为模拟用户点击或隐藏播放器而强行突破浏览器的许可决定**。

## v0.5.1：刷新后不自动播放的原因与修复

Holodex 的 `src/components/player/YoutubePlayer.vue` 在未启用 autoplay 时优先使用 `cueVideoById()` 加载媒体（等待用户或脚本启动），不会在刷新后无条件调用 `playVideo()`。YouTube IFrame API 同时受浏览器政策约束，`playVideo()` 可能触发 `onAutoplayBlocked`，特别是在没有用户交互时尝试**有声播放**。

v0.5.0 中还存在两种导致刷新无效的边界情况：

1. YouTube 刚初始化时处于 `-1`，过早调用 `playVideo()` 可能耗尽有限的重试次数；v0.5.1 对新出现的 `-1` 状态先等待约 **3.2 秒**（一旦变为 `5` 已加载待播放便立即尝试）。
2. 某些受限播放器先短暂进入播放，随后又被浏览器暂停；旧版可能错误保存为“手动暂停”并跨同一标签刷新继续保护。v0.5.1 不再将刚启动失败的暂停认定为用户暂停；要求观察到较稳定的播放状态，且远离最近自动播放请求与浏览器拒绝事件后才记录。原 v0.5.0 的潜在误判缓存不再继承，改用新的标签页会话键。

另外，Holodex 自带的 `VideoCell.updatePausedState()` 可能在首次播放某路视频时执行 `muteOthers()`。v0.5.1 在**脚本发起**的自动播放阶段暂时阻止这种首次自动启动对其他正在播放视频的静音影响；未成功启动并关闭功能时恢复 Holodex 原始首播标记。用户使用 Holodex 原生按钮主动播放仍保留原生控制行为。

### 新增逐路诊断

安装更新并**完整刷新**多视图后，从脚本菜单打开 **「诊断多视图自动播放状态」**；在自动播放设置面板也可以点击「查看每路自动播放状态与失败原因」。

| 诊断结果 | 说明及处理 |
| --- | --- |
| **没有识别到有效视频格子** | 等待 Holodex 多视图加载完成，确认当前格子是 YouTube，不是 Twitch / 聊天 |
| **等待播放器初始化** | 还未取得 `ytPlayer` 对象，或初始 `-1` 状态仍在等待；稍后重新诊断 |
| **已加载待播放** | YouTube 已 cue 媒体，脚本应准备尝试播放；查看尝试次数 |
| **浏览器已阻止自动播放** | 收到了 YouTube `onAutoplayBlocked`；页面内点击后可再次尝试，也可开启“失败后静音启动” |

| **脚本页面桥接尚未就绪** | 用户脚本未能与 Holodex Vue 播放器通信；检查 ScriptCat / Tampermonkey 是否启用以及页面完整刷新 |

**注意**：检测到“已发出播放请求”并不保证真的开始播放。即使修复所有脚本逻辑，也不能绕过浏览器的自动播放权限政策。声音设置仍默认**保持原有音量和静音状态**，没有擅自将所有视频静音；部分安卓浏览器必须在用户交互后才能启动有声视频。需要更高启动成功率时，可在设置中主动打开“多次失败后静音播放”。

## 新增：v0.5.0 智能自动播放（PC / Android）

自动播放模块集成在这个**独立 Touch Controls 脚本**中，不需要修改 Quick Add、HyperChat Cleaner 或 Channel Name Fix。该功能在电脑鼠标环境也正常运行，不要求有触摸屏。

### 自动播放触发时机

| 情况 | 策略 |
| --- | --- |
| 首次打开 Holodex 多视图 | 等待播放器就绪，尝试启动未开始或暂停但未被保护的视频 |
| 刷新页面或再次进入多视图 | 重连 Holodex 播放器后检查，每个视频的播放尝试次数有限 |
| Quick Add 或 Holodex 本身新增视频格子 | 周期性识别新格子并只尝试播放新加入及其他符合条件的视频 |
| 切回后台标签页 | 默认检查并恢复后台被中断的视频；可以关闭此行为 |
| 已在播放（state=1）或缓冲中（state=3） | **完全跳过，不调用 playVideo、不重置播放进度或音量** |
| 已经结束的录播（state=0） | 跳过，避免反复从头重播 |
| 用户主动暂停 | 如果在前台观察到从播放/缓冲变为暂停，则按该**视频格子**记录保护，自动扫描不重新播放 |

**手动暂停保护的范围与限制：**YouTube IFrame API 不会可靠告知“暂停是用户触发还是浏览器触发”，脚本只能用播放状态变化进行保守识别。新版本在持续播放约 6.5 秒、且距离最近的自动播放请求与拒绝事件足够久后，才对随后出现的暂停作保守判断；用户非常快速地手动暂停仍可能无法识别。它按布局格子 ID＋视频 ID 识别，每个 Holodex 标签页使用 `sessionStorage` 保存检测到的暂停，刷新同一标签页后继续尊重，记录限时 12 小时；重新开标签、改变布局 ID 或未观察到快速暂停时不保证保持这一状态。视频由用户重新启动后会清除该保护；手动菜单「立即尝试播放未播放的视频」会按你的明确指令临时跳过暂停保护。

### 自动播放设置（油猴菜单或设置面板）

从油猴菜单选择 **「智能自动播放设置（PC／安卓）」**，安卓也可在统计面板的「⚙ 设置」找到配置。默认值：

| 选项 | 默认 | 作用 |
| --- | --- | --- |
| 智能自动播放 | **开启** | 扫描未启动或非手动暂停的视频 |
| 切回标签时检查 | **开启** | 恢复后台被中断的播放 |
| 尊重手动暂停 | **开启** | 跳过已检测到的用户暂停 |
| 声音策略 | **保持原有音量与静音** | 不自动解除静音或改变其他视频的音量 |
| 受阻后静音启动 | **关闭（可选）** | 仅启用时在多次失败后尝试将该路静音再播放 |

设置先同步写入 Holodex 本地备份并立即更新播放器，再镜像写入脚本管理器。菜单提供明确的 **「▶ 开启智能自动播放」**、**「⏸ 关闭智能自动播放」**、**「立即尝试播放未播放的视频」** 和 **「诊断多视图自动播放状态」**。

### 浏览器自动播放限制与重试

- 通过 Holodex `VideoCell.ytPlayer.playVideo()` 发送播放请求，不模拟点击屏幕或刷新整个视频。
- **每路视频每轮最多 4 次普通自动播放尝试**，采用逐渐延长的等待；全部失败后停止连续重试。新增视频、重新切回标签页或重新启用功能可触发新的有限重试轮次，每路最多再追加 **2 轮**（正常自动尝试总上限 12 次，刷新页面后重新计算）。真实页面手势另有每轮最多 2 次的受控尝试，避免长时间无限轮询 `playVideo()`。
- 对尚未初始化的播放器等待后续扫描；对已播放的视频完全跳过。页面处于后台时不会主动播放，等标签返回再处理。对于前台首次缓冲就变为暂停的播放器，不会仅凭这一变化断言是用户手动暂停；只有观察到实际播放（含播放后缓冲）再转暂停才进行保护。
- 浏览器可能禁止无用户交互的有声播放；启用可选静音回退能提高部分播放器成功率，但**不保证全部浏览器有效**。保持声音设置是脚本默认策略。
- Quick Add v0.3.0 本身仍有**独立的新增视频静音回退机制**；因此如果同时安装 Quick Add，其自动添加新视频时的静音行为可能来自 Quick Add，不代表 Touch Controls 的默认声音设置失效。此次没有改动 Quick Add。
- 如果停用整个 Touch Controls 脚本，自动播放也随之停用；可以仅关闭「智能自动播放」而保留手机音量手势。

## 新增：灵敏度与长按配置

从油猴菜单选择 **「触控手势设置（灵敏度／长按）」**，也可在统计面板点击「⚙ 设置」。

**音量灵敏度**支持 **0.4×–2.5×**，默认 1.0×。可拖动滑块，也能直接选择：

| 预设 | 灵敏度 | 用途 |
| --- | --- | --- |
| 精细 | 0.6× | 小幅滑动、慢速调节 |
| 标准 | 1.0× | 默认 |
| 快速 | 1.6× | 小范围滑动较大音量 |

设置自动保存，下一次手势立即生效，不必刷新。

**统计触发方式**可选三种：

- **左侧轻点**：默认，保持原操作。
- **左右侧长按**：长按约 600ms 才打开统计，左侧轻点不再触发。
- **左侧轻点＋左右侧长按**：两种入口均可使用。

长按前手指移动超过约 12px 会取消长按；右侧滑动仍用于音量，避免长按与滑动同时触发。触摸取消、双指触摸或视频格子切换会清除或拒绝旧手势。笔输入有右侧音量基本后备支持。

## v0.4.1：为什么以前要开启原版统计才有实时带宽？

旧版先读取已有的 YouTube Stats for nerds DOM 内容，这些内容在原版统计被关闭后可能只是上一次的缓存值；即使随后调用 `getStatsForNerdsData()`，部分新值也会被旧 DOM 数据覆盖。

**现在采用两层修复：**

1. **先读取内部统计方法**，不再让原版统计已关闭时残留的 DOM 旧值覆盖数据。
2. 自定义面板打开期间，尝试通过 YouTube 的 `showVideoInfo()` 保持内部统计计算开启，同时仅将原版统计浮层设为**透明、不接收点击**，而不是 `display:none`。这样在自定义面板里可以继续尝试读取原版面板的活跃数据；点击「YouTube 原版统计」可以正常显示，再点击切回透明采集。
3. **关闭自定义面板**后停止隐藏采集并恢复打开前的原版统计显示状态。只针对当前选中的这一路视频操作，不会对所有直播同时开启统计。
4. 若 YouTube 不提供可确认的 `isVideoInfoVisible()` 或 `showVideoInfo()`，不强制启动原版面板，继续读取公开可访问的内部字段；数据不更新或不可用时不能保证显示实时带宽。

刷新频率不等于保证数据每次都变化：即使连续两次显示相同的 Mbps，也可能是 YouTube 自身的带宽估算暂未变化，不能简单判断脚本失效。

### 手机上快速收起统计

- **点击统计面板中上部任意统计区域**即可关闭：顶部标题、YouTube Connection Speed、Buffer Health、直播延迟、播放时间、当前／推荐分辨率，以及这些卡片间的空白区域。
- **点击统计面板外的画面中上部（包括原本属于 YouTube iframe 的位置）**即可收起。脚本仅在面板展开期间创建透明背景点击层，确保跨域 iframe 区域的轻点也能可靠关闭；收起后立即隐藏点击层，不阻挡正常观看。
- 原来的右上角 **×** 和 Escape 操作继续保留。
- **仅指标展示区域支持点按关闭**；下方的音量滑块、静音、±10、100%、原版统计和设置按钮保持原本交互，不会点一下就收起。

Connection Speed 与 Live Latency 并不是 YouTube 官方公开的稳定 IFrame API：`getStatsForNerdsData()` / `getStatsForNerds()` 等内部接口可能失效，脚本按数据是否存在显示，不会伪造、推算直播延迟或用 `navigator.connection` 替代 YouTube 网速。

## 调试与关闭手势

1. 从脚本管理器菜单点 **「显示/隐藏边缘触控区域（调试）」**：左侧蓝色、右侧绿色边界会显现。
2. 在绿色区域向上滑，检查是否出现音量卡片并且 Holodex 页面停止滚动。
3. 在蓝色区域轻点（或启用长按后按住左右区域约 600ms），检查是否打开统计。
4. 测试后关闭调试边界；视频画面不会有常驻图标。
5. 如果新增触控面积阻碍 YouTube 原生操作，可选 **「启用/禁用透明边缘手势」**，关闭后仍可从油猴菜单 **「选择视频查看统计（备用入口）」** 查看统计。

若连接速度、缓冲健康度、延迟全部显示「—」或提示 iframe 未响应，先检查脚本管理器是否准许在 YouTube 第三方 iframe 中运行。若只有直播延迟不可用，可能是当前视频不是直播或播放器不提供该内部字段。
