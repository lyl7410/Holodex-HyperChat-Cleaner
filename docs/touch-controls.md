# Holodex Touch Controls — v0.5.5 修复设置已开启但播放器代理仍关闭

针对 **Holodex Multiview 内的 YouTube 小播放器** 的独立油猴脚本。v0.5.5 针对新的实际截图：**Tampermonkey GM 主记录＝已启用、GM 旧键＝已启用、校验全部通过，但 Holodex 播放器代理的实际状态＝已关闭**。这不是单纯的设置保存失败，而是页面内播放器代理未在刷新启动时收到正确配置。新版直接在代理初始化时携带已读取的设置，附加状态核对和自动修复。保留安卓手势及原生统计。

**[安装 / 更新 v0.5.5](https://raw.githubusercontent.com/lyl7410/Holodex-HyperChat-Cleaner/main/userscripts/holodex-touch-controls.user.js)** · [项目首页](../README.md)

## 安装与升级

1. 在 PC 或安卓浏览器的 ScriptCat / Tampermonkey 中更新原有 **Holodex Touch Controls** 脚本，**不要同时启用两个版本**。
2. 刷新整个 `holodex.net/multiview` 页面。**自动播放支持 PC 与安卓**；左右音量手势和视频统计面板继续只在触摸设备上启用。功能只处理 Holodex 的 YouTube 视频格子，不针对普通 YouTube 观看网页、Twitch 或聊天格子。
3. 触摸手势和播放时间通过 Holodex 页面运行。**Connection Speed、Buffer Health、Live Latency 和原生分辨率**则还需要脚本获得在 `www.youtube.com/embed/*` / `www.youtube-nocookie.com/embed/*` 等第三方 iframe 内运行的权限。
4. 原来的 Cleaner、Quick Add、Channel Name Fix 不需修改。

## v0.5.5：GM 设置开启，但 Holodex 播放器代理关闭

用户在 v0.5.4 的真实诊断截图中看到：

| 诊断字段 | 实际值 |
| --- | --- |
| 状态（Holodex 播放器代理） | **已关闭** |
| Tampermonkey GM 主记录 | **已启用** |
| GM 旧键 | **已启用** |
| 存储校验 | **同步通过、异步通过、初始化完成** |
| 识别视频 | 1 路，已加载待播放，自动尝试 0 次 |

这意味着 GM 存储已经正确保存开启状态；问题在于页面内的播放器代理在刷新后仍使用默认的 `enabled:false`，或初始化后的配置消息未能使其一致。

### 代码修复

1. 之前页面代理的配置从硬编码的 `enabled:false` 起步，等待后续 `autoConfig` 消息。现在改为 **等篡改猴同步/异步存储读取完成后，才注入 Holodex 页面代理**。
2. 新版把四项实际设置**作为初始化参数直接交给页面代理**；代理创建时即处于正确状态，并马上尝试启动待播放视频。即使第一次配置 RPC 没有成功执行，首轮自动播放也不依赖它。
3. 完成代理的 `ready` 握手后，仍发送一次可校验响应的 `autoConfig`，确保代理与脚本管理器保持一致。
4. 多视图页面激活期间约每 6.5 秒检查一次代理的实际配置。若发现 GM 设置与代理不符，自动发起同步；不会反复重启正在播放或已缓冲的视频，播放失败本身仍有重试上限。
5. 诊断新增 **「代理启动：创建时已启用／创建时已关闭」**、**「状态匹配：一致／不一致」** 以及是否收到 RPC 配置，明确区分设置持久化、代理初始化与浏览器自动播放权限。
6. 若 GM 明确处于启用而代理仍处于关闭，将提示是**代理配置不一致**，不再错误要求用户反复点击“开启”。

### 篡改猴复测

1. 更新到 **v0.5.5**，确认只运行一份 Touch Controls，然后**完整刷新** `https://holodex.net/multiview`。
2. 在「诊断多视图自动播放状态」中检查 **状态：已启用**，同时确认 **代理启动：创建时已启用** 和 **状态匹配：一致**。
3. 如状态正确却仍显示 **「浏览器已阻止自动播放」**，代表配置恢复已经成功、阻碍来自浏览器允许播放的政策。这是独立问题，可在 Holodex 页面内尝试用户手势或启用“多次失败后静音”。
4. 如果仍发现 **「状态：已关闭，但 GM 主记录：已启用」**，请保留新的**代理启动／状态匹配／RPC 配置**诊断字段。它们能帮助识别代理注入失败、多个旧版脚本重复运行等剩余情况。

**验证边界：** 已在隔离模拟环境中测试了“GM 读取延迟 → 不提前注入代理 → 带入已启用配置 → 无需第二条 RPC 就发起播放”，以及代理被人为设置为关闭后自动检测并恢复。**尚未在真实安卓 Tampermonkey 中实测**。

## v0.5.4：Tampermonkey 启用后刷新重新变成关闭

用户在实际 **Tampermonkey** 环境反复遇到：菜单点击「▶ 开启智能自动播放」→ 当前页面能够尝试播放 → 刷新 → 诊断仍显示「状态：已关闭」。**v0.5.3 的 Holodex `localStorage` 优先备份不能保证消除此问题**，必须验证浏览器脚本管理器自身的存储，而不能只依赖网页存储。

### 修改方案

1. **篡改猴主记录**：新增独立的 `hmtc.autoplay.settings.canonical.v2`，一次记录全部四个自动播放布尔设置、版本号及修订号。明确开启/关闭时，调用已授权的 `GM_setValue` 同步写入，并通过 `GM_getValue` 当场读取校验。
2. **现代异步接口**：正式申请 `@grant GM.getValue`、`@grant GM.setValue`；同步 GM 写入之外，再通过现代接口保存、读取和校验。**篡改猴的传统 `GM_setValue` 本身是同步接口**，不同于某些其他脚本管理器的行为，v0.5.3 不应把篡改猴问题直接归因于写入异步。
3. **刷新时先恢复设置再启动**：页面加载时先检查 GM 主记录，随后读取异步 GM 主记录；**等待初始化读取完成**之后再下发 Holodex 页面内播放器的自动播放配置，防止旧的关闭状态参与首次启动。
4. **回退与兼容**：旧的独立 GM 设置键及 v0.5.3 Holodex 本地备份保留为回退数据；用户明确设置后优先使用有读回校验的 GM 主记录。网站的 `localStorage` 被限制时，GM 主记录仍可发挥作用。其他 Holodex 标签页的 GM 记录变化也可同步。
5. **诊断可追溯**：「诊断多视图自动播放状态」新增 `设置来源`、`GM 主记录：已启用／已关闭／未找到`、`GM 旧键`、`存储校验：同步／异步`、初始化是否完成，以及出现存储异常时的具体提示。
6. **提示更准确**：明确开启的菜单操作会等待持久记录校验结果，若播放设置已在页面生效、但持久化不能确认，会提示未完全成功；不再无条件称已经保存。

篡改猴官方 API 说明：[Tampermonkey Documentation — GM_getValue / GM_setValue / GM.getValue / GM.setValue](https://www.tampermonkey.net/documentation.php?locale=en&q=GM_values)。

### 本版安卓复测步骤

1. 在 Tampermonkey 扩展管理器中确认 **Holodex Touch Controls v0.5.4** 已安装、启用，并且旧版本没有重复启用。新版本增加了两个现代 GM API 授权项，升级时请允许扩展完成脚本更新。
2. 打开 `https://holodex.net/multiview`，从油猴菜单执行一次 **「▶ 开启智能自动播放（刷新后自动启动）」**。
3. 立即打开 **「诊断多视图自动播放状态」**。预期显示 **「状态：已启用」**、**「设置来源：Tampermonkey GM 主记录…」**、**「GM 主记录：已启用」**。
4. 完整刷新页面，重新打开同一诊断。预期 **状态和 GM 主记录仍是「已启用」**，而不是关闭。
5. 若状态已启用但视频仍处于「浏览器已阻止自动播放」，这是**另一个独立问题**：浏览器可能不允许无手势的有声自动播放。可在页面内做一次触摸交互并重试，或自行开启多次失败后静音回退；脚本不能保证绕过浏览器政策。

如果仍异常，请记录诊断中的 **设置来源、GM 主记录、GM 旧键、存储校验、存储提示**，以便区分 GM 写入未持久化、不同脚本实例、授权/注入问题及浏览器自动播放限制。不要清空全部浏览器数据作为第一步。

## v0.5.3：手动开启后刷新又恢复「已关闭」

用户的 v0.5.2 反馈表明：**诊断中点击确定开启后可以播放，但刷新 Holodex 多视图后总开关可能重新变成关闭。** 最新两张图片拍摄时显示「状态：已启用」，其中一张已尝试 4 次并提示浏览器拦截、另一张开启了「失败后允许静音」且正在等待下一次尝试。因此需要将 **开关持久化问题** 与 **浏览器限制有声自动播放问题** 分开处理。

### 此版本的修复

- 旧版：刚选择「启用」时，临时 JavaScript `Map` 能让当前页面立即播放，但是刷新后 `Map` 消失，下一次从 `GM_getValue` 恢复旧值，可能又是关闭。ScriptCat 官方说明 `GM_setValue` 后台写入可能是异步的；页面刷新过快会造成更新丢失。
- **v0.5.3：明确选择开启或关闭时，先同步写入当前 Holodex 域名下的 `localStorage` 持久备份**，然后再镜像到脚本管理器的 GM 设置。刷新后优先读取这份备份；即使原有 GM 值仍是「关闭」，明确的启用选择也不会丢失。
- 优先通过可 `await` 的 `GM.setValue` 进行脚本管理器写入，老式环境退回 `GM_setValue`；但**不会等待 GM 后台完成后才开始播放**。
- 四个设置均可同步保留：总开关、切回标签页时检查、手动暂停保护、失败后可选静音。
- **尊重明确关闭**：如果你选择关闭，也会跨刷新保存为关闭，不会每次启动强行打开。
- 两个同域 Holodex 标签页之间可通过本地存储变化通知同步设置。脚本存储备份只包含以上四个布尔开关，不存储账号或视频资料。

### 手机复测步骤

1. 更新到 **v0.5.3**，确保旧版本没有同时运行，完整刷新 Holodex 多视图。
2. 用脚本管理器菜单 **「▶ 开启智能自动播放（刷新后自动启动）」** 明确开启一次，或在诊断关闭提示中点「确定」。
3. 打开 **「诊断多视图自动播放状态」**，应看到 **「状态：已启用」**。诊断会增加 **「设置来源：Holodex 本地持久备份」**。
4. **再次刷新 Holodex**，重新打开诊断。预期仍为「已启用」，设置来源仍是本地备份。
5. 如果开关保持启用，但诊断依旧显示 **「浏览器已阻止自动播放」**，就是另一个问题——浏览器禁止无手势的有声播放。可以在页面内点一次再尝试，或自行启用失败后静音回退。**脚本无法保证绕过浏览器的自动播放策略。**

如诊断显示 **「Holodex 同源持久存储当前不可用」**，说明浏览器禁用了网站的 `localStorage`，此时只能尝试使用脚本管理器的存储，跨刷新一致性可能仍取决于该管理器实现。若使用 `www.holodex.net` 与 `holodex.net` 两种域名，需要注意各自的网站存储不互通，但脚本管理器存储通常在同一个脚本下共享。清除网站数据也会清掉对应域名的本地备份。

## v0.5.2：刷新不播放但诊断显示「状态：已关闭」

用户提供的 v0.5.1 诊断截图中，**两次都显示「智能自动播放 v0.5.1 · 状态：已关闭 · 识别：1 路」**。这说明脚本已经找到一个 YouTube 视频格子，但负责自动播放的总开关**当时已关闭**。旧版会继续展示「浏览器已阻止自动播放」的历史状态，或「已加载待播放／等待下一次自动尝试／尝试 0 次」，这些信息容易误导：开关关闭时根本不会继续自动扫描播放。**是否还有浏览器政策拦截问题，必须先启用自动播放后重新诊断，才能判断。**

### v0.5.2 处理方式

1. **明确开关**：旧版「开启／关闭智能自动播放」容易误按，拆分为「▶ 开启智能自动播放（刷新后自动启动）」与「⏸ 关闭智能自动播放」两个独立油猴菜单命令。**不会在升级时私自将已关闭状态重新开启**。
2. **诊断优先显示真实状态**：总开关关闭时，播放/等待统计信息统一注明「智能自动播放已关闭；此时不会尝试启动」，不再将旧的浏览器拦截或「等待下一次自动尝试」当作当前原因。
3. **诊断一键恢复**：从脚本菜单打开「诊断多视图自动播放状态」。若显示关闭，脚本会询问是否立即开启；点击**确定**后保存设置、同步播放器并再显示诊断。点击取消则保持关闭。
4. **设置状态明确可见**：「智能自动播放设置（PC／安卓）」里直接显示「当前已开启／当前已关闭」，开关保存后立即更新。
5. **异步脚本管理器兼容**：ScriptCat / 部分用户脚本管理器可能延迟持久化配置，旧版保存后立刻读取旧值有造成状态不同步的风险；新版暂存本页刚保存的值，再与播放器同步。诊断也会对存储状态与播放器状态不一致进行一次自动同步。
6. **重新开启后立即尝试**：若曾在关闭状态下手动尝试播放，再开启功能时会清理旧的重试冷却计数，给符合条件的待播放视频新的播放机会。

### 使用步骤

更新脚本到 v0.5.2 并完整刷新 `holodex.net/multiview`。可以直接点油猴菜单 **「▶ 开启智能自动播放（刷新后自动启动）」**，也可以先选择 **「诊断多视图自动播放状态」**，确认当前是关闭状态后点击确定启用。然后等待页面播放器加载，并重新查看诊断。

如果显示 **「已启用」且「浏览器已阻止自动播放」**，说明接下来需要解决的是浏览器的有声自动播放限制，而不是脚本的总开关。可在 Holodex 页面点一下尝试解锁用户手势，或主动开启「多次失败后静音启动」。浏览器是否允许实际播放由其自动播放策略决定，脚本不能保证绕过。

## v0.5.1：刷新后不自动播放的原因与修复

Holodex 的 `src/components/player/YoutubePlayer.vue` 在未启用 autoplay 时优先使用 `cueVideoById()` 加载媒体（等待用户或脚本启动），不会在刷新后无条件调用 `playVideo()`。YouTube IFrame API 同时受浏览器政策约束，`playVideo()` 可能触发 `onAutoplayBlocked`，特别是在没有用户交互时尝试**有声播放**。

v0.5.0 中还存在两种导致刷新无效的边界情况：

1. YouTube 刚初始化时处于 `-1`，过早调用 `playVideo()` 可能耗尽有限的重试次数；v0.5.1 对新出现的 `-1` 状态先等待约 **3.2 秒**（一旦变为 `5` 已加载待播放便立即尝试）。
2. 某些受限播放器先短暂进入播放，随后又被浏览器暂停；旧版可能错误保存为“手动暂停”并跨同一标签刷新继续保护。v0.5.1 不再将刚启动失败的暂停认定为用户暂停；要求观察到较稳定的播放状态，且远离最近自动播放请求与浏览器拒绝事件后才记录。原 v0.5.0 的潜在误判缓存不再继承，改用新的标签页会话键。

另外，Holodex 自带的 `VideoCell.updatePausedState()` 可能在首次播放某路视频时执行 `muteOthers()`。v0.5.1 在**脚本发起**的自动播放阶段暂时阻止这种首次自动启动对其他正在播放视频的静音影响；未成功启动并关闭功能时恢复 Holodex 原始首播标记。用户使用 Holodex 原生按钮主动播放仍保留原生控制行为。

### 新增逐路诊断

安装更新并**完整刷新**多视图后，从脚本菜单打开 **「诊断多视图自动播放状态」**；在自动播放设置面板也可以点击「查看每路自动播放状态与失败原因」。

| 诊断结果 | 说明及处理 |
| --- | --- |
| **没有识别到有效视频格子** | 等待 Holodex 多视图加载完成，确认当前格子是 YouTube，不是 Twitch / 聊天 |
| **等待播放器初始化** | 还未取得 `ytPlayer` 对象，或初始 `-1` 状态仍在等待；稍后重新诊断 |
| **已加载待播放** | YouTube 已 cue 媒体，脚本应准备尝试播放；查看尝试次数 |
| **浏览器已阻止自动播放** | 收到了 YouTube `onAutoplayBlocked`；页面内点击后可再次尝试，也可开启“失败后静音启动” |
| **普通自动尝试已用尽** | 有次数上限，防止循环；切回标签页、添加新视频或手动触发可开启受控重试 |
| **受保护的手动暂停** | 脚本保留用户已经暂停的视频；可使用明确的手动「立即尝试播放」命令覆盖 |
| **脚本页面桥接尚未就绪** | 用户脚本未能与 Holodex Vue 播放器通信；检查 ScriptCat / Tampermonkey 是否启用以及页面完整刷新 |

**注意**：检测到“已发出播放请求”并不保证真的开始播放。即使修复所有脚本逻辑，也不能绕过浏览器的自动播放权限政策。声音设置仍默认**保持原有音量和静音状态**，没有擅自将所有视频静音；部分安卓浏览器必须在用户交互后才能启动有声视频。需要更高启动成功率时，可在设置中主动打开“多次失败后静音播放”。

## 新增：v0.5.0 智能自动播放（PC / Android）

自动播放模块集成在这个**独立 Touch Controls 脚本**中，不需要修改 Quick Add、HyperChat Cleaner 或 Channel Name Fix。该功能在电脑鼠标环境也正常运行，不要求有触摸屏。

### 自动播放触发时机

| 情况 | 策略 |
| --- | --- |
| 首次打开 Holodex 多视图 | 等待播放器就绪，尝试启动未开始或暂停但未被保护的视频 |
| 刷新页面或再次进入多视图 | 重连 Holodex 播放器后检查，每个视频的播放尝试次数有限 |
| Quick Add 或 Holodex 本身新增视频格子 | 周期性识别新格子并只尝试播放新加入及其他符合条件的视频 |
| 切回后台标签页 | 默认检查并恢复后台被中断的视频；可以关闭此行为 |
| 已在播放（state=1）或缓冲中（state=3） | **完全跳过，不调用 playVideo、不重置播放进度或音量** |
| 已经结束的录播（state=0） | 跳过，避免反复从头重播 |
| 用户主动暂停 | 如果在前台观察到从播放/缓冲变为暂停，则按该**视频格子**记录保护，自动扫描不重新播放 |

**手动暂停保护的范围与限制：**YouTube IFrame API 不会可靠告知“暂停是用户触发还是浏览器触发”，脚本只能用播放状态变化进行保守识别。新版本在持续播放约 6.5 秒、且距离最近的自动播放请求与拒绝事件足够久后，才对随后出现的暂停作保守判断；用户非常快速地手动暂停仍可能无法识别。它按布局格子 ID＋视频 ID 识别，每个 Holodex 标签页使用 `sessionStorage` 保存检测到的暂停，刷新同一标签页后继续尊重，记录限时 12 小时；重新开标签、改变布局 ID 或未观察到快速暂停时不保证保持这一状态。视频由用户重新启动后会清除该保护；手动菜单「立即尝试播放未播放的视频」会按你的明确指令临时跳过暂停保护。

### 自动播放设置（油猴菜单或设置面板）

从油猴菜单选择 **「智能自动播放设置（PC／安卓）」**，安卓也可在统计面板的「⚙ 设置」找到配置。默认值：

| 选项 | 默认 | 作用 |
| --- | --- | --- |
| 智能自动播放 | **开启** | 扫描未启动或非手动暂停的视频 |
| 切回标签时检查 | **开启** | 恢复后台被中断的播放 |
| 尊重手动暂停 | **开启** | 跳过已检测到的用户暂停 |
| 声音策略 | **保持原有音量与静音** | 不自动解除静音或改变其他视频的音量 |
| 受阻后静音启动 | **关闭（可选）** | 仅启用时在多次失败后尝试将该路静音再播放 |

设置先同步写入 Holodex 本地备份并立即更新播放器，再镜像写入脚本管理器。菜单提供明确的 **「▶ 开启智能自动播放」**、**「⏸ 关闭智能自动播放」**、**「立即尝试播放未播放的视频」** 和 **「诊断多视图自动播放状态」**。

### 浏览器自动播放限制与重试

- 通过 Holodex `VideoCell.ytPlayer.playVideo()` 发送播放请求，不模拟点击屏幕或刷新整个视频。
- **每路视频每轮最多 4 次普通自动播放尝试**，采用逐渐延长的等待；全部失败后停止连续重试。新增视频、重新切回标签页或重新启用功能可触发新的有限重试轮次，每路最多再追加 **2 轮**（正常自动尝试总上限 12 次，刷新页面后重新计算）。真实页面手势另有每轮最多 2 次的受控尝试，避免长时间无限轮询 `playVideo()`。
- 对尚未初始化的播放器等待后续扫描；对已播放的视频完全跳过。页面处于后台时不会主动播放，等标签返回再处理。对于前台首次缓冲就变为暂停的播放器，不会仅凭这一变化断言是用户手动暂停；只有观察到实际播放（含播放后缓冲）再转暂停才进行保护。
- 浏览器可能禁止无用户交互的有声播放；启用可选静音回退能提高部分播放器成功率，但**不保证全部浏览器有效**。保持声音设置是脚本默认策略。
- Quick Add v0.3.0 本身仍有**独立的新增视频静音回退机制**；因此如果同时安装 Quick Add，其自动添加新视频时的静音行为可能来自 Quick Add，不代表 Touch Controls 的默认声音设置失效。此次没有改动 Quick Add。
- 如果停用整个 Touch Controls 脚本，自动播放也随之停用；可以仅关闭「智能自动播放」而保留手机音量手势。

## 新增：灵敏度与长按配置

从油猴菜单选择 **「触控手势设置（灵敏度／长按）」**，也可在统计面板点击「⚙ 设置」。

**音量灵敏度**支持 **0.4×–2.5×**，默认 1.0×。可拖动滑块，也能直接选择：

| 预设 | 灵敏度 | 用途 |
| --- | --- | --- |
| 精细 | 0.6× | 小幅滑动、慢速调节 |
| 标准 | 1.0× | 默认 |
| 快速 | 1.6× | 小范围滑动较大音量 |

设置自动保存，下一次手势立即生效，不必刷新。

**统计触发方式**可选三种：

- **左侧轻点**：默认，保持原操作。
- **左右侧长按**：长按约 600ms 才打开统计，左侧轻点不再触发。
- **左侧轻点＋左右侧长按**：两种入口均可使用。

长按前手指移动超过约 12px 会取消长按；右侧滑动仍用于音量，避免长按与滑动同时触发。触摸取消、双指触摸或视频格子切换会清除或拒绝旧手势。笔输入有右侧音量基本后备支持。

采用深色半透明圆角面板，适应手机横屏／竖屏：

| --- | --- | --- |

## v0.4.1：为什么以前要开启原版统计才有实时带宽？

旧版先读取已有的 YouTube Stats for nerds DOM 内容，这些内容在原版统计被关闭后可能只是上一次的缓存值；即使随后调用 `getStatsForNerdsData()`，部分新值也会被旧 DOM 数据覆盖。

**现在采用两层修复：**

1. **先读取内部统计方法**，不再让原版统计已关闭时残留的 DOM 旧值覆盖数据。
2. 自定义面板打开期间，尝试通过 YouTube 的 `showVideoInfo()` 保持内部统计计算开启，同时仅将原版统计浮层设为**透明、不接收点击**，而不是 `display:none`。这样在自定义面板里可以继续尝试读取原版面板的活跃数据；点击「YouTube 原版统计」可以正常显示，再点击切回透明采集。
3. **关闭自定义面板**后停止隐藏采集并恢复打开前的原版统计显示状态。只针对当前选中的这一路视频操作，不会对所有直播同时开启统计。
4. 若 YouTube 不提供可确认的 `isVideoInfoVisible()` 或 `showVideoInfo()`，不强制启动原版面板，继续读取公开可访问的内部字段；数据不更新或不可用时不能保证显示实时带宽。

刷新频率不等于保证数据每次都变化：即使连续两次显示相同的 Mbps，也可能是 YouTube 自身的带宽估算暂未变化，不能简单判断脚本失效。

### 手机上快速收起统计

- **点击统计面板中上部任意统计区域**即可关闭：顶部标题、YouTube Connection Speed、Buffer Health、直播延迟、播放时间、当前／推荐分辨率，以及这些卡片间的空白区域。
- **点击统计面板外的画面中上部（包括原本属于 YouTube iframe 的位置）**即可收起。脚本仅在面板展开期间创建透明背景点击层，确保跨域 iframe 区域的轻点也能可靠关闭；收起后立即隐藏点击层，不阻挡正常观看。
- 原来的右上角 **×** 和 Escape 操作继续保留。
- **仅指标展示区域支持点按关闭**；下方的音量滑块、静音、±10、100%、原版统计和设置按钮保持原本交互，不会点一下就收起。

Connection Speed 与 Live Latency 并不是 YouTube 官方公开的稳定 IFrame API：`getStatsForNerdsData()` / `getStatsForNerds()` 等内部接口可能失效，脚本按数据是否存在显示，不会伪造、推算直播延迟或用 `navigator.connection` 替代 YouTube 网速。

## 调试与关闭手势

1. 从脚本管理器菜单点 **「显示/隐藏边缘触控区域（调试）」**：左侧蓝色、右侧绿色边界会显现。
2. 在绿色区域向上滑，检查是否出现音量卡片并且 Holodex 页面停止滚动。
3. 在蓝色区域轻点（或启用长按后按住左右区域约 600ms），检查是否打开统计。
4. 测试后关闭调试边界；视频画面不会有常驻图标。
5. 如果新增触控面积阻碍 YouTube 原生操作，可选 **「启用/禁用透明边缘手势」**，关闭后仍可从油猴菜单 **「选择视频查看统计（备用入口）」** 查看统计。

若连接速度、缓冲健康度、延迟全部显示「—」或提示 iframe 未响应，先检查脚本管理器是否准许在 YouTube 第三方 iframe 中运行。若只有直播延迟不可用，可能是当前视频不是直播或播放器不提供该内部字段。
